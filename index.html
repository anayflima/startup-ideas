Company of companies

Build many products inside one company and run them all on a shared AI machine.

A venture-funded company of companies. We build several products inside one company, each aiming for millions and then tens of millions in ARR. A shared AI company machine runs GTM, onboarding, support and ops for all of them. We keep the companies and don't sell the machine.
$570MRippling ARR, built as many products in parallel
$1.31BBending Spoons revenue on one shared stack
55+apps Zoho runs on one platform
$3B+raised by Thrive Holdings for AI-run portfolios

How it works

1

Pick a focused market that pays for software and is too small for the AI labs to care about.

2

A small pod does the 0 to 1: customer calls, product shape, first users.

3

The machine runs it: landing page, LinkedIn, outbound, onboarding, support, ops.

4

Double down or kill: PMF earns people and money, no traction gets shut down fast.

Why now

  • Big horizontal TAMs are where the labs go next (a lab already shipped a Granola-type notes app). Focused markets stay below their radar.
  • AI made building cheap. Running a company is now the bottleneck, and that is what the machine does.
  • We're funded, so we can run several bets in parallel and hire a platform team early.

Later: buy companies

With cash flow, buy stagnant software companies (they sell for about 3.5 to 5.5x ARR) and move them onto the machine, like Bending Spoons does with Evernote, WeTransfer and Vimeo.

Why it could work

  • Many shots on goal; one failed product doesn't kill the company.
  • The machine compounds: every launch makes the next one cheaper and faster.
  • Focused markets avoid head-on fights with the labs.
  • Investors already fund this shape (Rippling, Bending Spoons, Thrive Holdings).

What could go wrong

  • Distribution is the hard part. The machine speeds up execution, not finding demand.
  • Focus: several half-built products instead of one great one.
  • The portfolio must add up to a venture-size outcome ($100M+ ARR).
  • Burn grows fast if the kill rules are soft.

Open questions

  • Same buyer for every product (like Rippling) or unrelated markets (like Bending Spoons)? Still open: build or buy, see Latest thinking and Buyers we studied.
  • One brand or many brands under one parent?
  • How many pods at once: 3, 5 or 8?
  • When do acquisitions start? Current answer: when we hit the milestones in Latest thinking.

Next steps

  • Pick 3 to 5 focused B2B markets to test (filter in Playbook).
  • Decide the first machine pieces: GTM machine, auto onboarding, self-healing support.
  • Talk to 2 or 3 multi-product operators (lempire, saas.group, Bending Spoons alumni).

What we worked out on 18–19 Nov. Short version: decide build vs. buy (our machine is mostly a buying advantage); let each customer reshape the product; build what gets better as AI models improve; and make every bet a step toward the AI rollup.

1. Build or buy? (still open)

Rippling and Bending Spoons are different models, not two versions of ours:

  • Rippling builds many products for the same customer on one data layer.
  • Bending Spoons runs unrelated products for different markets, but buys them with product-market fit already found. That's its whole advantage: it skips finding fit, the risk that building takes on every time.
  • So: our shared AI machine is mostly a buying advantage. Building unrelated products from scratch means finding product-market fit again each time, which AI doesn't solve. The stories are in Buyers we studied.
  • Exception: the media tool stays as our existing product and proof that we can run a product with AI. Parker Conrad (Rippling) on the “compound startup” is saved in Videos.

2. One product that each customer can change

“Malleable software”: one base product per buyer, and each customer asks for changes in plain language (“add a parking field,” “monthly owner report in French”). AI makes the change for that customer only.

  • Fits small firms that each work a bit differently: off-the-shelf frustrates them, custom software is too expensive.
  • Repeated requests tell us what to build for everyone.
  • Many customer versions to maintain: limit what can change (settings, fields, automations, reports) and keep core logic fixed.
  • Wrong changes are costly, so changes are drafted, tested and approved.
  • Selling the customization tech itself is crowded; we use it inside our own products.

Companies doing this: Gigacatalyst (YC Spring 2026; reports 800+ custom configurations, company-reported), Vendo (YC Summer 2026), Malleable. Warning: Builder.ai promised AI-built custom apps and collapsed in 2025 amid allegations of overstated revenue.

3. Build what gets better as models improve

Gohar asked whether this is what Pentagon (YC P26) was doing. Pentagon built a workspace where AI agents coordinate like a team, the same category as The Company Company. We heard the founder moved on because the models themselves are learning to coordinate agents, so a separate tool for it stops being a company (not publicly confirmed).

Made unnecessary by better modelsMade more valuable by better models
Agent managers and coordination toolsOwning businesses with customers and revenue
Tools that patch today's AI weaknessesBusinesses where AI does the work
Probably agent workspaces over timeDistribution, trust, customer relationships
  • For us: every model upgrade makes the companies we run cheaper to operate. We benefit from the labs instead of competing with them.
  • Rent the machine, don't over-build it: use tools like The Company Company month to month, keep workflows simple enough to switch, and only build what we need now.

4. The path: company of companies first, rollup next

  • Why this order: investors want proof before funding acquisitions (General Catalyst reportedly looks for ~30% of tasks automated). Running products with AI is that proof, and our own profits mean less dilution.
  • Risk: running small software products isn't the same as running service firms, and buying firms is a separate skill. The Swiss window may close (Treuhand was taken in 2026).
  • Fix: make the next bet the first step of the rollup: an AI back office for Swiss property managers, starting with tenant calls and emails (10–30 a day). It's a product now, the acquisition pipeline later, and the machine that runs the firms we buy.

Raise for the rollup when we hit (our assumptions):

  1. 10+ property managers paying.
  2. AI handles 50%+ of tenant inquiries.
  3. 3–5 owners open to selling, and one letter of intent.
  4. The media tool runs on under 5 hours a week.

5. An edge without knowing every industry

  • Specialize in a type of business, not an industry, like Bending Spoons (consumer subscription apps) or Constellation (niche vertical software). Pricing, churn and support tactics carry over between industries.
  • Borrow industry knowledge: keep sellers on as advisors, or partner with specialists.
  • An audience helps the parent company, not each product. Thomas's followers bring sellers, investors and hires; they aren't the buyers of a niche B2B tool. Each product still needs its own channel.

The stories

Bending Spoons (Italy, 2013): buys products that already have product-market fit
  • Origin: started with ~$40k left over from a failed startup (Evertale). Lesson: finding product-market fit is mostly luck; running a product well can be learned. First acquisition ~$10k (2014).
  • Big deals: Evernote (~$200M, 2023), Vimeo ($1.38B), AOL, Eventbrite (~$500M); Airtable and Miro agreed in late 2026. Nasdaq IPO July 2026 ($1.68B raised); Berkshire Hathaway invested $900M+.
  • Only buys businesses with $50M–$5B revenue and predictable retention, at ~3–5x profit after planned changes.
  • Playbook: cut staff (Evernote 341 → 60), centralize everything, raise prices 2–4x, rewrite the product with AI (90%+ of code changes AI-written).
  • Numbers (company-reported): revenue $387M (2023) → $1.31B (2025); ~$30B market value (Oct 2026); $4.4B debt.
  • Weak spots: existing customers spend less each year (net revenue retention 91–95%), so growth needs more deals; backlash over layoffs and price increases (Evernote $70 → $130/yr).
Constellation Software (Canada, 1995): buys industry software, never sells
  • Origin: Mark Leonard (ex-venture capital) raised ~C$25M and bought software companies he already knew (transit scheduling, utility billing).
  • Today: 1,100+ businesses in 9 groups, 76–123 deals a year (median ~$3M), $11.6B revenue (2025).
  • Light center: headquarters only allocates money and sets a minimum return per deal (est. 20–30%). Headquarters costs 0.9% of revenue; returns rose as it shrank: “trust trumped central bureaucracy.”
  • Weak spots: organic growth only 2–4%; shares fell 50%+ in 2026 on fears AI hurts industry software. Leonard stepped down in 2025 (health).
Topicus (Constellation's European group)
  • Origin: Constellation bought the Dutch buyer TSS in 2013 (~€240M); merged with Topicus.com and listed in 2021.
  • Today: €1.32B revenue in 9 months of 2026 (+18%, 5% organic), 26 countries, ~€390M of acquisitions in 2025 plus a large stake in Asseco Poland.
  • DACH: has a dedicated DACH M&A director, but no confirmed Swiss acquisition found. If we bought Swiss software, we'd often bid against them.
saas.group (Cologne, 2017): buys small SaaS, central team as a menu
  • Origin: Tim Schumacher's first deal (~$1M) used money from his earlier exit; later deals mostly debt.
  • Buys: bootstrapped, profitable SaaS with $1–10M ARR in North America and Western Europe, at ~2–3x ARR, 7–8 deals a year. $100M+ ARR (Mar 2026), 25+ brands.
  • Model: each brand keeps its CEO; marketing, finance and AI are optional central services.
Tiny (Canada, 2016): what goes wrong
  • Funded by profits from the MetaLab design agency; listed 2023.
  • Debt became “too high,” assets were sold, and a C$80.7M write-down hit in 2026 because AI hurt two businesses. Tried a stronger center and backed away.
Studios that build instead (Atomic, Hexa, Rocket Internet)
  • Atomic: one huge win (Hims) carries the portfolio. Hexa: ~3 unicorns from ~40 companies. Rocket Internet: copied US models, ~4 big winners from 100+.
  • Lesson: building is still a power-law bet on finding product-market fit. Buying skips that risk.

For us: our shared AI machine is a heavy center, so it only fits similar businesses. Small property managers all do the same work (tenant messages, service-charge statements, owner reports), so one machine can run them all.

How we'd be different from them

  1. Buy what they don't: service firms. All of them buy software; none buys property managers or Treuhand firms.
  2. AI changes services far more than software. Software already earns 20–40% margins; service firms ~5–10% because most cost is people doing repetitive work. AI can double or triple that.
  3. A heavy center that fits: similar firms, one AI machine, without Bending Spoons' problem of very different products.
  4. A better offer for sellers: Constellation's “permanent home” plus “we keep your team and AI takes the boring work,” instead of mass layoffs. It solves the owner's succession problem.
  5. Local trust: Swiss languages, laws and relationships that US buyers can't easily copy.

A draft of how a new product goes from idea to running on the machine.

A market passes when

  • B2B buyers already pay for software or services in it.
  • There's a reachable channel: a community, marketplace, SEO or a clear outbound list.
  • Too focused for the labs, big enough for $5-20M ARR.
  • Testable in 4 to 6 weeks.
  • Fits our backgrounds or shares a buyer with another product.

The company machine

  • GTM: landing page, LinkedIn page, daily posts, outbound, ads.
  • Auto onboarding and product tours.
  • Self-healing support and ops agents.
  • Shared auth, billing, analytics and one dashboard.
  • A launch template for every new product.

Stages and gates

1

Explore, 2-4 weeks: 20+ customer calls, a landing page, a waitlist or letters of intent.

2

Build, 4-6 weeks: MVP on shared auth, billing and onboarding; first paying users.

3

Prove, ~90 days: no paying customers or no MRR growth means kill it and keep the learnings.

4

Scale: steady MRR growth and good retention earn a bigger pod.

5

Run: the machine runs it; humans move to the next product.

Capital rules (our assumptions)

  • Fixed budget per pod per stage; money follows the gates.
  • At about $10M a year of spend: platform team $3-4M, 6 to 8 pods at $0.5-0.8M each.
  • Acquisitions use a hurdle rate, like Constellation (~20-25% IRR).

Small bets and next ideas: pushback, engine, traps, Thomas, the monthly playbook and the 8 researched ideas

The pushback

1. The trading analogy doesn’t hold
  • Trading strategies run independently at almost no cost. Products compete for the same attention and distribution.
  • Products get better with focus. Five products with a fifth of your attention each tend to stall.
  • A few big winners produce most startup returns. Small bets help you find the winner, not build it.
2. A startup studio has a hiring problem
  • The best solo founders won’t trade most of their equity for a salary, so you’d mostly attract weaker ones.
  • A salary plus “move on if it fails” removes the urgency that drives founders.
  • Better as a later stage, once you have a proven playbook and a brand.
3. AI-only support has a trust ceiling
  • Paying business customers who only get a bot when they hit a wall often cancel.
  • AI-only support works for cheap self-serve products, but those earn little per customer.
  • Low revenue per customer means you need scale, which brings you back to selling.
Other pushbacks
  • Selling doesn’t split: five products means five audiences and five channels.
  • 5 hours a week only holds before you have users. Customers bring support, bugs and churn.
  • Ignored niches are often ignored because they’re too small to be worth it.
  • Funding: to investors, a set of small products reads as a lifestyle business.

The engine and the traps

The engine: 3 things to do

  • Ideation: AI scans Reddit and reviews for complaints. The edge comes from what we know that others don’t (Pavoot customers, events).
  • Build: AI builds tests in days. Aim for 1–2 weeks per test.
  • Sell: AI researches leads and drafts messages. Real conversations win the first customers.

3 traps

  • AI marketing gets ignored: people are learning to tune out AI-generated messages, so talk to people yourself.
  • AI ideas are generic: everyone’s AI suggests the same ones. Use AI to filter and test ideas, not to come up with them.
  • Building the engine instead of selling: run tests by hand first, and automate a step only after repeating it 2–3 times.

Test: could AI ideation have found the media tool?

No. Searching “event photos” turned up 15+ selfie-matching tools and platforms that already include it, so the obvious conclusion was not to build. The VIP/press angle (Zurich Film Festival) only came up because Ana pointed to it.

  • AI ideation finds loud problems, not quiet ones. Loud problems (consumer, many users, lots of posts) are already crowded. Quiet problems (specific professions like festival press offices, who don’t post on Reddit) are where good small businesses are.
  • Reddit ideas get you crowded ideas. The fix: have AI read our own data (Granola meetings, support messages, sales calls), not the internet.

How the media tool idea actually happened

  1. Proven model elsewhere: Scoreplay already did it for sports.
  2. Bad market dropped in discussion: influencers were discussed and dropped, with nothing built.
  3. A real person picked the market: a classmate running an event had the problem.
Lesson: AI can produce the “X for Y” options. Closeness to real people decides which one is worth building.

From the Small Bets notes: one product test per month. AI does the volume, real people decide.

Where ideas come from (AI does the volume)

  • Proven models: AI lists models that work in one industry or country (US → DACH, sports → events) and suggests new markets for each.
  • Our own data: AI reads Granola meetings, Pavoot customer messages and the people in our network for problems that come up repeatedly.

Filter: an idea moves forward only if

  • A real person we can reach has the problem today.
  • They’d pay (a pilot, deposit or letter of intent).
  • It can’t be copied in a weekend (needs local knowledge, integrations, or trust).

Part 1: The economics
  • Purchase prices: small professional-services firms ~3–5.5x EBITDA; larger ones 6–8x; top platforms 9x+ [3P]. Large take-privates cost far more (Baldwin ~20x).
  • Valuation once rolled up: 6–8x for traditional services, ~10x for platforms, 12–18x if valued like software [3P].
  • Claimed margin gains [CR]: GC from 5–10% to 30–40%; Gil gross margin ~10% to 40%; Mayfield 80–90% gross margin if AI does 80% of the work.
  • Typical deal structure [3P]: 60–80% cash, 10–20% seller rolls into equity, 10–25% earn-out tied to clients staying, 5–15% seller note.

Part 1: Criticism and failures
  • No AI rollup failure found yet, and no public data on clients leaving.
  • Closest precedents: Renovo Home Partners (a PE remodeling rollup; Chapter 7 in Oct 2025, ~$500M of liabilities); Amazon-seller aggregators (Thrasio and others) mostly failed; a 2008 HBR finding: two-thirds of rollups were value-neutral or worse.
  • Integration is hard: different systems in every firm, so AI rollout is “patchy and slow.” GC’s Bhargava: “it’s really hard to transform a company with AI.”
  • The “workslop” tension: cut staff and fewer people catch AI errors; keep them and margins don’t move.
  • Investor skepticism: Slow Ventures says accounting assets are “insanely competitive” and LLMs might even destroy value; Bessemer says there’s no “magic AI accounting product” and the base case is a good PE deal; PitchBook: “the math doesn’t make sense.”
  • Staff sentiment: in PE-backed CPA firms, over half of staff are dissatisfied and 56% expect clients to suffer (trade survey).

How to test it cheaply (one month)

  1. Talk to 5 Treuhand owners about succession and what takes up their team’s time.
  2. Talk to 2 business-sale brokers (e.g. KMU Nachfolgezentrum, transactionpartner.ch) about prices and how many firms are for sale.
  3. Pick one routine task (e.g. bookkeeping or VAT filing) and test how much of it AI can do on real (anonymized) data.

Go if: owners are open to selling, prices make sense, and AI can handle a large share of the routine work.

Geopolitical event insurance

Insurance against wars and big political events in the countries a business depends on.

A company with a factory, team, suppliers or customers in a country buys cover against a war, coup, sanctions or unrest there. If it happens, it gets paid fast on a clear trigger, without proving every euro of loss.

Why now

  • Ukraine, Israel and Gaza, the Red Sea and Taiwan made war risk a board-level topic.
  • Normal property and business interruption policies exclude war, and insurers tightened those exclusions after 2022.
  • Parametric insurance is proven in weather (about $12B of premium, growing about 12% a year) and is moving into violence and politics.
  • AI makes it cheap to price and pay small policies, the thing that kept SMEs out.

In numbers (check before quoting)

  • About $7B a year of stand-alone political risk premium (2025), growing 6 to 9% a year.
  • $49B counting all credit, political risk and surety (Howden).
  • Best venture comparable: Descartes Underwriting, about $250M of premium in 2025.
  • Almost all buyers today are large companies, banks and project investors.

The gap a startup could take

  • SMEs and mid-market: today it is broker-led, custom-quoted, slow and priced for big projects.
  • Non-damage losses: classic cover pays when your building is destroyed. Lost revenue, stuck staff and broken supply chains are mostly uncovered.
  • Speed: claims take months. A parametric trigger can pay in days.
  • Embedded: sold inside payroll and employer-of-record tools, freight and trade finance platforms, travel tools.

Reports define these markets very differently, so ranges are wide. Premium = what customers pay per year. Check every number before quoting.

Premium pools

  • Credit, political risk and surety: about $49B of premium in 2025 (Howden, Opportunity in flux).
  • Stand-alone political risk (war, political violence, expropriation, currency): about $7B in 2025, growing 5.8 to 8.8% a year to 2030. Wider definitions go up to about $35B.
  • Political violence and terrorism: about 34% of that, so roughly $2.4B. Lloyd’s alone writes roughly $1.5B to $2.3B.
  • Parametric insurance (all risks): about $12B of premium in 2025, about 12% a year.
  • Terrorism: Pool Re (UK) collects about £150M to £200M a year; US terrorism cover under TRIA is several $B a year.
  • Kidnap and ransom: $0.45B to $2.6B depending on the report.

How much is insured

  • Berne Union members: about $34.5B of new political risk cover in 2025, down about 18%.
  • MIGA: record $9.5B of new guarantees in FY2025, $36.8B total exposure.
  • Ukraine: Lloyd’s war capacity about $600M a year; EBRD and Aon facility of €150M, reinsured by MS Amlin.
  • Capacity is the bottleneck: the demand exists, the risk appetite does not.

Adjacent markets

  • Prediction markets: $44B traded in 2025 (Polymarket $21.5B, Kalshi $17.1B). Kalshi made $263.5M in fees in 2025.
  • Risk intelligence: Dataminr about $200M revenue in 2025; Seerist about $14M (estimate).
  • Travel security and evacuation: International SOS about $1.5B revenue, Crisis24 about $250M.

What it means for a startup

  • The classic market is about $7B, mostly big buyers through brokers. The SME and parametric slice is tiny today: that is both the opening and the risk.
  • An MGA earns a commission on premium, typically about 20 to 30% (assumption). So $100M of premium is about $20M to $30M of revenue.
  • Reaching Descartes size ($250M premium) would mean roughly $50M to $75M of revenue.

It exists, mostly for big companies and through brokers. Insurers report premium, not revenue; numbers shown where public.

What changes

  • Live pricing: models read news, ACLED, satellite, shipping (AIS) and airspace data and reprice each country every week, instead of one broker quote that takes weeks.
  • Near-zero underwriting cost: a $2k policy becomes worth writing (assumption).
  • Machine-checkable triggers: airspace or border closed, port shut, sanctions listing, conflict events within a radius. Payout in days.
  • Exposure mapping: an agent reads a customer’s suppliers, staff locations and invoices, shows what is at risk and quotes cover.
  • Embedded by API: quote and bind inside payroll, freight or travel tools.
  • Before, not only after: alerts and evacuation help as risk rises, then the payout.

What AI does not fix

  • Correlation and capacity: carriers and reinsurers still have to take the risk.
  • Wars are rare, so models are hard to prove to Lloyd’s and regulators.
  • Customers read the news too: adverse selection gets faster.
  • Incumbents buy the same tools (Federato, Cytora, Concirrus).
  • Real-time signal is already owned by Dataminr and similar players.

Where an AI-native player can win

  • Small tickets, fast quotes, automatic claims, sold embedded where SMEs already are.
  • Software first: an AI underwriter for Lloyd’s political risk syndicates (submission triage, live exposure, pricing). Revenue sooner, no capital; later become the MGA on their capacity.

What could go wrong

  • Correlated risk: one war hits every customer in that country at once. That is why capacity is small and reinsurers exclude war.
  • Adverse selection: people buy right before a war. Insurers stop writing new policies as soon as tension rises, exactly when demand peaks.
  • Little data: wars are rare, so pricing is hard to defend with models alone.
  • Trigger disputes: what counts as a war? Parametric triggers have basis risk (the event happens but the trigger does not fire, or the other way around).
  • Regulation: needs a licensed carrier and an insurable interest, otherwise it is a betting product.

What makes it workable

  • Start as an MGA: we design, price and sell; a Lloyd’s syndicate or reinsurer carries the risk. Capital-light, the standard insurtech path.
  • Spread exposure across many countries and cap cover per country.
  • Annual policies with waiting periods, not cover bought the week before a war.
  • AI on news, conflict and satellite data for pricing, monitoring and automatic payouts. Fits our ML background.
Real and growing, but not new: big companies already buy about $7B a year of it. The opening is a fast, parametric, AI-priced product for SMEs and mid-market, built as an MGA on an existing carrier, or as software for those insurers first.

Good

  • Large, growing premium pool and a clear gap (SMEs, lost revenue, slow claims).
  • Recurring revenue; Descartes shows parametric can reach $250M of premium and a $120M Series B.
  • Data and ML are the edge in parametric pricing and triggers.

Bad

  • Neither of us has an insurance background: we need an underwriter co-founder or advisor and a carrier partner early.
  • Broker-led distribution, long sales cycles, regulation in every country.
  • Capacity can disappear exactly when the world gets dangerous.
  • Slower to show traction than software.

Possible wedges to test

  • War and evacuation cover for companies with remote staff or contractors in risky countries, sold inside employer-of-record and payroll tools.
  • Parametric supply chain cover that pays if a key route (Red Sea, Taiwan Strait) or a supplier country is disrupted.
  • An AI underwriter sold to Lloyd’s political risk syndicates (software revenue, no capital).
  • Event and trip cancellation from political unrest, a niche we know from Pavoot.

Next steps

  • Talk to 5 to 10 SMEs that operate in or source from risky countries: do they want it and what would they pay?
  • Talk to 2 or 3 Lloyd’s political risk underwriters and an MGA founder (e.g. Skyline Partners) about capacity and what software they would buy.
  • Check if it fits the company of companies machine or is a separate, regulated company.

Simulate your users first

Build AI copies of your customers and let them test everything before real users do.

Before you ship, build a synthetic population of your ICPs: agents that act like your buyers (high or low intent, rude or polite, a human decision-maker or an agent buying for one). They give feedback 24/7, help write PRDs, click through your onboarding and react to your messaging. Real A/B tests come later, on what survived.

Where it came from

  • A VC/advisor shared it with Ana before the Kaszek founders event (5 Aug 2026), as step 1 of a framework for agentic B2B growth.
  • His claim: this replaces a lot of A/B testing and becomes the normal way to optimise funnels by 2027.
  • Step 2 of his framework: run growth loops against the synthetic users (onboarding, invites, collaboration, reuse, community, lifecycle).

Why now

  • LLM agents can now use real browsers and apps, so a persona can actually go through a signup flow, not just answer a survey.
  • Big money is going in: Simile raised a $200M Series B at about $2B, Aaru about $1B valuation (check before quoting).
  • Early-stage teams have little traffic, so classic A/B tests take weeks or never reach significance.
  • Agents are becoming buyers too: “agent-assisted” customers need testing as a persona of their own.

Why it could work

  • Forces engineering and marketing to write down the ICP precisely. Teams find blind spots (“I don’t actually know X about them”).
  • Feedback in minutes, not weeks, and for almost nothing per run (local models keep token cost low).
  • Works with little data: seed personas from competitor scrapes, past flows, call notes and market behaviour.

What could go wrong

  • Synthetic users are too average: LLMs smooth out the weird, contradictory behaviour real users have.
  • Good for finding friction and generating hypotheses, weak for predicting what people will pay for.
  • Crowded fast: well-funded players at the top, many small QA-agent startups at the bottom.

The playbook as described in the conversation, plus what the research adds.

1

Define 2 to 3 ICPs precisely: role, company, goal, budget, objections, tools they use.

2

Build agent versions from your own data (customer calls, meeting notes, CRM) or, if you have little, from competitor scrapes and market behaviour.

3

Add flavours: high vs low intent, rude vs polite, human vs agent-assisted. Grow to 15+ personas over time.

4

Run them through everything: landing page, onboarding, pricing page, emails, PRDs. Log where they get stuck or leave.

5

Move the denominator: send agents to look for edge use cases and underserved groups. When metrics plateau, build the next ICP.

6

Check against reality: confirm the big findings with a few real users or a real A/B test before betting on them.

The growth loops to test (from the note)

  • Onboarding, outcome to growth (he cited about 90% of Nubank users inviting others before getting their card), collaboration, data improvement, reuse/remix, programmatic authority, community, lifecycle.

Two groups: “simulate people” (research, strategy) and “simulate users in the product” (QA, onboarding). Numbers from web search, check before quoting.

Simulating people (research, strategy)

  • Simile: Stanford spin-out from Joon Sung Park (the 2023 “generative agents” paper). Reported $200M Series B at about $2B. Clients reported: CVS, Deloitte, Wealthfront.
  • Aaru: multi-agent simulations of consumers and voters. Reported $80M Series A led by Redpoint at about $1B headline value. Works with Accenture, EY, IPG.
  • Artificial Societies (YC W25): simulates how groups and audiences react. Reported $5.35M seed.
  • Synthetic Users: AI user interviews and concept tests. Enterprise plans reported from about $12.5K a year.
  • Evidenza: AI copies of hard-to-reach B2B buyers, sold as a managed research service.

Simulating users in the product (QA, onboarding)

  • Mimiq: AI personas run your live site in real browsers and report dead ends and confusion.
  • Simulithic (YC): maps user flows and explores web apps like real users across devices.
  • TesterArmy (YC): vision agents run natural-language tests through onboarding.
  • Minds and others: synthetic panels to pre-test flows before spending real traffic.
  • Related, already on our watch list: Hue (fake worlds to test agents).
Two ways to use it: as a tool inside our company machine (every product we build gets synthetic users from day 1), or as a product of its own.

As an internal tool (low risk)

  • Fits the company of companies: each new product starts with 2 to 3 synthetic ICPs and is tested before launch.
  • Seed from our own data: customer calls, Granola notes, meeting logs.
  • Pairs with the analytics and “talk to users” layer we discussed (Userlens-style), and with automated launch videos.

As a product (needs a wedge)

  • Top of market is taken by Simile and Aaru (enterprise research). The QA end is full of small YC teams.
  • Possible wedge: B2B onboarding and PLG funnels for early-stage startups, tied to their real analytics so the personas are checked against real behaviour.
  • Another wedge: testing how AI agents (not humans) evaluate and buy your product.

Next steps

  • Build 2 to 3 synthetic ICPs for one of our ideas, from our customer data and meeting notes.
  • Run them through one real flow and compare with what real users did.
  • Decide: keep as internal tool, or worth a product.

Accuracy

  • Studies find LLM personas match broad survey trends fairly well (often quoted 75 to 85%), but compress diversity and miss contradictions (NN/g and others).
  • They struggle with new contexts and with real behaviour (what people do vs what they say).
  • Researchers treat them as hypothesis tools, not decision-grade validation.

Business

  • Hard to prove ROI: if a synthetic test says “fine” and real users churn, trust is gone.
  • Well-funded competitors and a low technical barrier.
  • Personas are only as good as the data behind them; early startups have little.
Great as a habit, risky as a company. Use it now inside our machine for every product we test. As a stand-alone startup it only makes sense with a sharp wedge (startup PLG funnels tied to real analytics, or agent-buyer testing), because the big “simulate people” market already has $1B+ players.

Self-improving agents for repetitive work that get smarter and cost less with every run. A managed agent platform for ops work that needs research and judgment.

Hue (YC F26)

Realistic worlds for agent evaluation: stateful clones of the apps an agent works in, so teams can test it on real-looking tools, data and state before it reaches users.

What it is

  • Hue simulates the apps an agent uses (Gmail, Slack, Salesforce, Notion, QuickBooks). The agent uses them like the real ones, without touching any live account.
  • Founders Aneesh Kethini (CEO; second AI PM at Datadog, built and launched Datadog’s AI SRE; before that quant trader at SIG) and Josh Le (CTO; engineering at Apple, Gusto, Wayfair, SendBlue, Sixtyfour). YC F26, team of 2, San Francisco.

How it works

  • Generate worlds: a coding agent describes the setup to test against (for example the apps of a 40-person software company that just raised a Series B) and Hue fills them with months of realistic history in a couple of minutes.
  • Start from real runs: Hue reads agent traces and rebuilds the state of the world at that moment, so a production failure can be reproduced and the fix verified.
  • Run the agent from the same starting point as many times as needed, set up evals to score it, and compare versions before shipping.

Why it’s worth knowing

  • Agents now send emails, update CRMs and issue refunds, but there is no safe place to test them: live inboxes are off limits, mock APIs are not realistic and sandbox tenants start empty. Hue bets that testing is the next agent infra layer.
  • Any shared machine running many agent products, like our company of companies, needs this kind of test harness. Also close to our AWS for agent automations idea.
